## 1. Главная страница

### Что хорошо
- Поиск в центре, сайт сразу понятен.
- Чистая типографика, достаточно воздуха.
- Статистика (29 014 этюдов) добавляет доверия.

### Что улучшить
1. **Фильтры появляются только при фокусе на поле автора.** Это скрытое поведение: пользователь не знает, что фильтры вообще есть. Проблемы:
   - на телефоне нет "наведения", фокус случаен, панель может раскрыться неожиданно и сдвинуть страницу;
   - при потере фокуса (клик в другое поле панели, прокрутка) панель может схлопнуться, и введённые значения не видны;
   - скринридеры и клавиатурные пользователи не получают сигнала, что открылись новые поля;
   - новый посетитель видит единственное поле и не догадывается о поиске по материалу, теме, дате.

   Решение: оставить панель закрытой по умолчанию, но открывать её явной кнопкой "Расширенный поиск ▾" (с `aria-expanded`), запоминать состояние и показывать счётчик активных фильтров ("Фильтры: 2"). Фокус на поле автора панель не переключает.
2. **Вертикальный ритм.** Заголовок "Search by:" почти прилипает к линии под меню. Использовать единый шаг отступов (например, 24 px).
3. **Подпись "author:"** не выровнена с полем ввода. Поставить подпись над полем или выровнять по центру.
4. **Кнопки.** "Make query" должна быть главной (залитая), "Clear form" вторичной (контурная или текстовая). Увеличить зазор между кнопками. Переименовать "Make query" в "Search" / "Найти".
5. **Пустая зона** между разделителями до первого запроса. Заполнить блоками "Случайный этюд", "Этюд дня", популярными авторами.
6. **Заголовок** капсом слишком крупный и конкурирует с формой. Уменьшить в 1,5-2 раза, сделать ссылкой на главную.
7. **Автодополнение** в поле автора (Kubbel / Kubbel L / Кюббель).
8. **Статистика.** Сделать компактнее, пояснить термины: "from composers", "from users".

## 2. Расширенный поиск

Поля: автор, число белых и чёрных фигур (от/до), условие, тема, дата, "Is cooked".

- Подписать понятно: "Белых фигур: от … до …", добавить placeholder и подсказки.
- "Theme": заменить свободный текст на автодополнение или мультивыбор популярных тем.
- "Is cooked": переключатель из трёх состояний (любые / только корректные / только с дефектами) с пояснением термина.
- Разделить на "Основные" (автор, условие, тема) и "Дополнительные" (материал, даты, cooked), раскрывать по клику.
- Enter в любом поле запускает поиск, есть кнопка "Сбросить".

## 3. Страница результатов

### Что хорошо
- Диаграммы видны сразу.
- Есть PGN и PDF.
- Штриховка тёмных полей хорошо подходит для печати.

### Что улучшить
1. **Выравнивание.** Длинное название ("Listok Shakhmatnogo Kruzhka Petrogubkom") переносится на две строки и сдвигает доску относительно соседних. Решение:

```css
.study-card .title {
  min-height: 3.6em;
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
.study-card .pid {
  font-size: 0.75rem;
  color: #888;
}
```

2. **Иерархия.** Сейчас крупнее всего "PID : 1411" (технический идентификатор). Поднять автора, источник и год, PID сделать мелким серым.
3. **Порядок блоков:** подпись, доска, кнопки (сейчас кнопки сверху).
4. **Кнопки.** "PGNLIVE!" и "GET PGN" тяжелее самих данных. Заменить компактными иконками или меню "⋯": Открыть в PGNLive, Скачать PGN, Копировать FEN.
5. **Расшифровка условия.** `tt22#016 {m}` превратить в "Мат в 16 ходов", сырой код оставить в подсказке. Год выводить как "1916" (на продакшене это уже сделано).
6. **Чей ход.** Добавить "Ход белых" / "Ход чёрных", условие ("Белые выигрывают" / "Ничья"), число фигур.
7. **Заголовок результатов.** Исправить "no more then 1000 diagrams per PDFfile" на "не более 1000 диаграмм в одном PDF-файле". "get pdf" сделать кнопкой "Скачать PDF".
8. **Стрелка ➤** под заголовком без подписи. Если это пагинация, заменить номерами страниц или кнопкой "Показать ещё".
9. **Сортировка:** по году, автору, числу фигур. Показывать общее число найденных позиций.
10. **Оформление карточки:** тонкая рамка или лёгкий фон, отступы между карточками.
11. **Доска:** координаты (a-h, 1-8), мягкая серая заливка на экране (штриховку оставить для PDF), клик открывает увеличенный вид.

## 5. Навигация и структура
- **"Гамбургер" справа скрывает меню аутентификации.** Иконка читается как "навигация", а не "вход", и на десктопе скрывать нечего. Вывести в шапку текстовую ссылку "Войти" (и "Регистрация", если есть); после входа показывать имя или аватар с меню (Профиль, Избранное, Выйти). Гамбургер оставить только для узких экранов, и пусть он открывает всё меню целиком. Добавить `aria-label`. Если у аккаунта есть польза (избранное, история запросов), сказать об этом один раз: "Войдите, чтобы сохранять этюды".
- `About` и `Links` открываются через `?q=about` на главной. Сделать отдельные адреса (`/about`, `/links`).
- Адрес `/endgame//` содержит двойной слэш, исправить настройку путей.
- "FENBuilder" подписать понятнее: "Конструктор позиции (FEN)".
- **Критично:** после поиска адрес остаётся `endgame.md/endgame/`. Хранить параметры в URL:

```
/endgame/?author=Kubbel&stipulation=win&sort=year
```

- Пустой результат: подсказка "Ничего не найдено. Попробуйте убрать фильтр".
- Индикатор загрузки при поиске по базе.

- Одноколоночная форма на телефоне, поля высотой не менее 44 px.
- Контраст текста, видимый фокус, `<label for="...">`, `aria-label` у иконок (включая "гамбургер").
- Всё управляется с клавиатуры, у доски есть текстовая альтернатива (FEN).
- Адаптивная сетка карточек: 3 колонки на десктопе, 2 на планшете, 1 на телефоне:

```css
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 24px;
}
```
